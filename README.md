# Phoenix build times

How fast can a realistic Phoenix app compile on the latest Erlang/OTP, Elixir and
Phoenix `main`, and what does it take to make it faster?

[`shop/`](shop/) is generated by [`bench/generate-app.sh`](bench/generate-app.sh): `phx.new`
(SQLite), `phx.gen.auth`, and 40 `phx.gen.live` resources in 8 contexts with 160 LiveView routes.
That makes 194 `.ex` files and 752 tests. [`bench/measure.sh`](bench/measure.sh) reports
hyperfine medians on an Apple Silicon laptop (12 cores).

## Results

| scenario | released¹ | main² | **optimized³** |
|---|---|---|---|
| deps compile (cold) | 15.32s | 16.63s | **5.23s** (−66%) |
| app compile (cold) | 2.46s | 2.69s | **1.77s** (−28%) |
| no-op compile | 0.47s | 0.44s | **0.42s** |
| edit router | 1.51s | 1.72s | **1.34s** (−11%) |
| edit core_components | 0.90s | 0.92s | **0.74s** (−18%) |
| edit schema | 0.56s | 0.51s | **0.48s** |
| edit context | 0.61s | 0.61s | **0.52s** |
| edit liveview | 0.62s | 0.65s | 0.68s |
| test env compile (cold) | – | 2.60s | **1.79s** (−31%) |

1. Elixir 1.19.6, Erlang/OTP 28.5, Phoenix 1.8.16, LiveView 1.2.13 (`bench/release-shell.sh`)
2. Elixir main (1.21.0-dev), Erlang/OTP master (30-dev), Phoenix and LiveView `main`, no changes
3. main² plus every optimization below

Every edit recompiles exactly one module on all toolchains: Elixir 1.19+ tracks dependencies
precisely, and the generated code only has runtime dependencies between modules. The edit times
are mostly Mix startup (0.42s) plus that one module.

## Optimizations

### 1. Compile dependencies in parallel processes: deps −46%

Elixir 1.19+ can compile dependencies in several OS processes. Four was the sweet spot on 12
cores (more processes contend over the few big dependencies):

| `MIX_OS_DEPS_COMPILE_PARTITION_COUNT` | 1 | 4 | 8 | 12 |
|---|---|---|---|---|
| deps compile | 16.58s | **8.90s** | 9.58s | 9.95s |

### 2. Skip the Erlang compiler's optimizations in dev and test: −30 to −40%

Profiling with `ERL_COMPILER_OPTIONS='[time]'` shows that 70-80% of every module's compile time
is spent in the Erlang compiler, mostly in `beam_ssa_opt`. Those passes make code faster at
runtime but don't affect correctness; the `beam_debug_info` option turns them off for debugger
builds. Development and test builds don't need them:

```elixir
# shop/mix.exs
elixirc_options: elixirc_options(Mix.env())

defp elixirc_options(:prod), do: []

defp elixirc_options(_env) do
  [
    module_definition: :interpreted,   # Elixir 1.20+, ~6% on its own
    erlc_options: [:no_ssa_opt, :no_copt, :no_bsm_opt, :no_bool_opt,
                   :no_share_opt, :no_recv_opt, :no_throw_opt]
  ]
end
```

| cold app compile | time |
|---|---|
| default | 2.65s |
| `no_ssa_opt` | 1.97s |
| all `no_*_opt` | 1.91s |
| all `no_*_opt` + `module_definition: :interpreted` | **1.84s** |

`elixirc_options` only applies to the app's own modules. [`devenv.nix`](devenv.nix) also sets
`ERL_COMPILER_OPTIONS` to the same flags, which covers the dependencies: with 4 partitions
the deps compile goes from 8.77s to **5.23s**. `shop/mix.exs` refuses `MIX_ENV=prod` builds while
that variable disables optimizations, so they can't leak into a release. All 752 tests pass on
the unoptimized build.

Turned out not to matter: `infer_signatures: false` (−3%) and `debug_info: false` (−2%).

### 3. Router: group clauses per HTTP verb: router −17%

The router is the biggest module: 160 LiveView routes compile into a 1.1 MB `.beam`, and
`__match_route__/3` is one function with a clause per route. Phoenix `main` has an option that
splits it per verb:

```elixir
use Phoenix.Router, helpers: false, group_by: :verb
```

It requires `forward` and `match :*` routes to come last, so the generated dev routes block
(LiveDashboard, Swoosh mailbox) moved to the end of the router.

### 4. Phoenix fork: one shared `prepare` function: router −18%

Each route clause compiled its own closure just to merge path params and the route's
compile-time `private`/`assigns` into the conn: 180 extra functions for the Erlang compiler.
[onnimonni/phoenix@`router-shared-prepare`](https://github.com/onnimonni/phoenix/tree/router-shared-prepare)
returns that data as a literal instead, shared by one `Phoenix.Router.Route.prepare/3`. Route
metadata, telemetry and `route_info/4` are unchanged, and all 1,113 Phoenix tests pass. Router
compile: 765ms → 630ms. Upstream PR: [phoenixframework/phoenix#6888](https://github.com/phoenixframework/phoenix/pull/6888).

### 5. Erlang/OTP fork: a compiler crash on master

OTP master (4ba5448, 2026-10-30) can't compile the `decimal` library:

```
internal error in pass beam_validator_strong: bad argument in float/1
  in call from beam_types:norm_number/1
```

`beam_types:norm_number/1` converts number range bounds to floats, and `decimal` compares
against `10^2000`, which is beyond the float range. It was introduced in 6fc2465974 ("Fix
`argument_widened` assertion").
[onnimonni/otp@`fix-norm-number-bigint`](https://github.com/onnimonni/otp/tree/fix-norm-number-bigint)
keeps such integers as they are, with a regression test in `beam_type_SUITE`. Upstream PR:
[erlang/otp#12121](https://github.com/erlang/otp/pull/12121). The smallest
module that crashes the unpatched compiler, found by shrinking `Decimal`'s abstract code:

```erlang
f(I) when I < 1 bsl 1100 -> I;   % I is a number range starting beyond the float range
f(I) -> g(I).
g(0) -> 0;
g(I) -> g(I div 3).              % widening g/1's argument type hits norm_number/1
```

[`devenv.nix`](devenv.nix) builds that fork, plus Elixir `main`, from source.

## What's left

* **Router edits (1.34s).** After compiling the router, Elixir's type checker spends ~155ms
  on it and ~315ms re-checking the 132 modules that use its verified routes. Most of the router
  time comes from types inferred for huge literal-returning functions such as `__routes__/0`:
  the type-checker chunk (`ExCk`) is 815 KB of the 1.1 MB `.beam`. Widening inferred types of
  large literals in Elixir would help every big router.
* **Mix startup (0.42s)** is a floor for every incremental compile.
* **HEEx-heavy modules** (`core_components`, LiveView forms) cost 100-200ms each, mostly in the
  Erlang compiler even with optimizations off.

## Reproduce

```sh
devenv shell                       # Erlang/OTP master + Elixir main, built from source
bench/generate-app.sh shop         # regenerate the app (or use the committed one)
cd shop && ../bench/measure.sh . 7

bench/release-shell.sh 'cd shop && ../bench/measure.sh . 5'   # released toolchain
```
